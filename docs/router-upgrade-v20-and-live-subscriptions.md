# Обновление роутера: WDTT Plus v20 и подписки Xray без перезапуска

## WDTT Plus

Основа: Ivan4537/WDTT-Plus, тег v20, commit d450e132d2477a80d7079282c200ac3fb97ad0ae (релиз 30 сентября 2026).

ARM64 Linux, CGO=0, Go 1.26.8. Локальный SOCKS5 127.0.0.1:1088 с UDP ASSOCIATE, без замены глобальной сети. Сохранены пароль, device_id, ручные хеши, адрес и порты сервера. Автоматическое создание звонков остаётся выключенным.

Перенесены изменения клиента v19/v20: TCP/TLS без внешнего UDP/HTTP3, согласование transport-experiment=auto с новым сервером, транспортные очереди и восстановление каналов. Старый патч chunk=64 не переносился на новый диспетчер автоматически: его поведение изменилось upstream. Единственный исходный router-патч — расширение SOCKS concurrency 64→256 и журнал отказов; исходники транспорта/WireGuard не подменялись. GOMAXPROCS=2 ограничен процессом клиента.

Воспроизводимая сборка: `router/build-wdtt-plus-v20.sh /absolute/build-directory` при установленном Go 1.26.8. Все исходники/кэши внутри указанного каталога. Лицензия GPLv3 сохраняется в пакете вместе с upstream pin и patch.

## Xray

Ручное обновление в окне подписок раньше выполняло hardRestart, автоматическое — soft_restart. Оба пути заменены управлением через localhost API:

1. Получить/проверить новый список; при ошибке сохранить рабочую конфигурацию.
2. Добавить изменённые outbounds с отдельными runtime tag, не удаляя прежние обработчики.
3. Через RoutingService направить новые соединения на новое поколение. Статические теги в сохранённом JSON/интерфейсе остаются прежними; runtime-map отдельный, привязан к PID/starttime.
4. Балансировщики получают только текущие поколения; Observatory сохраняет совместимые префиксы.
5. Сохранить JSON атомарно. При ошибке восстановить правила через API; запрещён автоматический restart процесса/firewall.

Не изменяются inbounds, DNS, WAN, обходы устройств, локальные/direct/CSQTT/WDTT outbounds. В ручном пути отдельно проверяется неизменность правил 192.168.0.4. Общий замок предотвращает пересечение обновления и изменений маршрутов.

Для живого обновления нужны HandlerService и RoutingService на 127.0.0.1:18085. На осмотренном роутере есть только RoutingService: добавление HandlerService требует одного первоначального перезапуска Xray. До отдельного разрешения он не выполняется. При отсутствии API автообновление сохраняет pending в /opt/etc/xkeen, ручное возвращает ошибку; старая сеть работает. Pending не лежит в confdir и не загружается ядром случайно.

Старые обработчики сохраняются до следующего запланированного человеком restart, чтобы не оборвать существующие соединения. При 128 subscription handlers обновление откладывается вместо бесконечного роста памяти. Уже отозванные провайдером реквизиты сохранить работоспособными нельзя. Цепочки dialerProxy требуют отдельной реализации и отклоняются.

## Что взять из статьи и ролика

Текст статьи прочитан полностью. В ролике нет доступных субтитров: выводы о нём основаны на описании и README указанного автором проекта, а не на подтверждённой расшифровке озвучки.

Полезные дальнейшие переносы:
- Раздельная диагностика прямого WAN, DNS, процесса, маршрута и фактического выхода через выбранный туннель.
- Последняя рабочая конфигурация, проверка до замены, атомарная запись и один замок для всех операций.
- Обновлять подписку при отказе узлов, сохраняя прежние узлы при недоступности подписки; загрузка не должна зависеть только от уже умершего туннеля.
- Несколько контрольных адресов, повторные ошибки и задержка перед переключением; ограничение частоты восстановления.
- Экран «почему нет интернета», ограниченный журнал и ручная диагностика без исправлений по умолчанию.
- Резервные копии и воспроизводимые обновления с проверкой опубликованных хешей/подписей; отказ от неподтверждённого latest.

Не переносить буквально: OpenWrt procd/fw4/nft/TUN конфигурацию в Keenetic/Entware/iptables; network restart и reboot из сторожа; глобальное выключение IPv6/блокировку DNS приложений без отдельной настройки; проверку VPN только по loc!=RU (русский выход может быть намеренным). 3X-UI KIT — установщик VPS, его серверный набор протоколов не является установщиком клиента для роутера.

Эти идеи — обзор возможных следующих изменений. Новая автоматика, Telegram-уведомления и перезагрузки этим коммитом не включаются.
